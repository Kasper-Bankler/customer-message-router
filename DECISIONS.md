# Decision log

Judgment calls only: choices a reviewer could reasonably have made differently,
with what was given up. Routine choices are not logged — if the alternative was
obviously worse, it does not belong here.

The point of this file is that "why did you do it that way?" has a written answer
before the question is asked.

Assumptions live in `ASSUMPTIONS.md`; this file records choices, not premises.

| Date | Decision | Rationale | Alternatives considered |

| 2026-08-08 | Orchestration is plain Python function calls in `src/pipeline.py`, not LangGraph | Every line is explainable under questioning, and the agents stay pure functions, so swapping in LangGraph later is a wiring change rather than a rewrite | LangGraph — named in the job ad and maps 1:1 to the architecture diagram, but adds framework behaviour I would have to defend as my own |
| 2026-08-08 | `proposed_action`, `escalation` and `token_cost` are typed Pydantic submodels, not bare `dict` | The pitch is typed I/O contracts; untyped escape hatches in the most important model would undercut it on the schema slide | Bare `dict` as originally specced — less upfront design, but defers the field set to whoever writes the agent |
| 2026-08-08 | `ollama` is the only LLM SDK installed; the Azure OpenAI path is described in `llm.py` but not depended on | The prototype runs fully locally, so no customer data leaves the machine — a genuine asset in a banking interview | Installing `openai` too for a hosted demo fallback; rejected for now to keep the "runs offline" claim clean |
| 2026-08-08 | Numeric fields carry explicit bounds (`injection_score`, `confidence`, `sla_minutes`, `latency_ms`) | A malformed structured-output response fails validation at the boundary instead of silently propagating a nonsense score into the policy matrix | Unbounded floats as originally specced |
| 2026-08-08 | `similarity` and `relevance` are left unbounded while the other floats are bounded to [0,1] | Cosine similarity can be negative and RRF scores are not in [0,1]; bounding them would reject valid values | Bounding every float for consistency — rejected as wrong for these two specifically |
| 2026-08-08 | Models do **not** set `extra="forbid"` | Required fields are still enforced, so a malformed response is still caught; silently dropping a hallucinated extra key is the preferred failure mode over raising on one | `extra="forbid"`, which is stricter on LLM structured output but turns a harmless extra key into an exception on the customer path |

| 2026-08-08 | `Escalation.suggested_reply` added now rather than in a later session | PLAN §2 already has the handoff agent producing a draft for the human agent, so the field is known; adding it now avoids a schema change once agents are written against the contract | Holding strictly to the eight models in §5 and amending later |
| 2026-08-08 | Added `src/cli.py` as the demo entry point | The demo shows `RoutingDecision` JSON, and the Streamlit UI is first on the cut list, so the primary entry point must not depend on it | A `__main__` block in `pipeline.py`; rejected to keep wiring separate from presentation |
| 2026-08-08 | `pip install -e .` via a minimal `pyproject.toml` is the documented install | Makes `src` importable from `eval/`, `tests/` and `app/` in one move; running `python eval/run_eval.py` otherwise fails outright, which I confirmed rather than assumed | A `sys.path` shim at the top of each script — works, but is the kind of line that invites "why is this here?" in every file it appears in |
| 2026-08-08 | `requirements.txt` carries lower bounds only for now, with exact pins to follow from `pip freeze` | The upper bounds I had written were guesses I had not checked against PyPI, and a wrong guess blocks a clean-clone install — the exact pins land once the stack is known to work | Keeping guessed major-version caps; rejected because an unverified cap is worse than none |
| 2026-08-08 | Language detection uses `langdetect`, with its weakness on short strings documented rather than engineered around | Banking77 messages are short, so this will misfire; measuring that in the adversarial suite is a better presentation than a heavier dependency and an unmeasured claim | `lingua` (more accurate on short text, much larger) or a hosted detector; both add weight for a gap that is more honest to quantify |
| 2026-08-08 | Package structure flattened: no single-file packages. A directory exists only where there is more than one file and a real reason to group them | `guardrails/`, `retrieval/`, `tools/` and `observability/` each held one or two files, so the directory added a path segment and an `__init__.py` without adding meaning. `agents/` keeps four genuinely parallel files and survives | Keeping PLAN §4 verbatim — tidier on a slide, but four packages that exist only to hold one module each is exactly the ceremony the complexity budget rules out |
| 2026-08-08 | The action agent lives in `tools.py` with the registry, not as a separate `agents/action_agent.py` | The agent is a thin layer over the registry — it picks a tool and fills its argument schema. Splitting them puts two halves of one idea in two files that always change together | A standalone action agent module, parallel to the RAG and handoff agents; rejected because the symmetry is cosmetic |
| 2026-08-08 | `graph.py` renamed to `pipeline.py` | "Graph" is LangGraph vocabulary for something that is a straight line of function calls; the name would invite a question the code cannot support | Keeping `graph.py` to match the architecture diagram's shape |
| 2026-08-08 | Banking77 is fetched as two CSVs from PolyAI's GitHub over `urllib`, not via `datasets.load_dataset("PolyAI/banking77")` | The Hub entry is a loader *script*, and `datasets>=3` refuses to execute those (`RuntimeError: Dataset scripts are no longer supported`); no parquet conversion is published either. The script's own download URLs give byte-identical data — 13,083 rows, the same 77 labels — with no remote code execution, which is the better answer in a banking review anyway. `datasets` is now removed from `requirements.txt` | Pinning `datasets<3` to keep the one-liner — rejected because running downloaded code to get a CSV is hard to defend here |
| 2026-08-08 | Embeddings are `BAAI/bge-small-en-v1.5`, English-only | Both the FAQ corpus and Banking77 are English. Non-English messages are stopped at ingress by language detection, so they never reach retrieval — a multilingual model would cost four times the size for a path that is never taken | `intfloat/multilingual-e5-base`, which PLAN §3 lists first and would allow a Danish retrieval demo; the Danish story is now told by the ingress lane instead |
| 2026-08-08 | FAQ coverage threshold is cosine 0.77, chosen by hand-inspecting the ranked list rather than tuned | All 77 best-match scores fall in a narrow 0.63–0.89 band, so no natural gap exists. Reading down the ranking, matches stay topically correct to `transfer_not_received_by_recipient` (0.774) and the first wrong one is `exchange_rate` (0.767), whose best article quotes an FX *fee* and never a rate. The cut is that break, and it is stated as a judgment rather than an optimum | Tuning against a labelled coverage set — there is no such labelled set, and inventing one to justify a threshold is circular. Or picking a round 0.75, which would let `exchange_rate` in and quietly break the abstention demo |
| 2026-08-08 | Coverage is measured intent-centroid to article, accepting known false negatives | It is PLAN §6's method and it is one number per intent, which is what a chart needs. The centroid is a lossy summary though: `receiving_money`, `country_support` and `automatic_top_up` each have a genuinely relevant article but score below the cut. So the map understates coverage, which is the safe direction for an abstention story | A per-message hit rate (share of an intent's training messages that clear the gate) — more faithful to how retrieval actually runs, but it introduces a second threshold that cannot be justified until the retrieval gate itself is tuned |
| 2026-08-08 | `autoreply_allowed` is deliberately redundant with `disposition`, and `check_safety_invariants` enforces agreement in both directions | Two independent switches mean one careless edit cannot open the auto-reply path on a fraud row. Redundancy that is machine-checked costs nothing and is exactly the defence-in-depth argument the panel will ask for | A single `disposition` field — less to keep in sync, but then one wrong word in a 550-line YAML file is the only thing between a fraud message and an automated answer |
| 2026-08-08 | `Domain` is an enum in `taxonomy.py`, not in `schemas.py`, and keeps `lending_products` despite it having zero Banking77 intents | Domains are a property of the routing table, so they belong with it; `schemas.py` holds the inter-agent contract only. Keeping the empty domain records a real finding — the FAQ has five lending articles the taxonomy can never reach, so lending arrives as out-of-taxonomy and routes to human, which agrees with the no-advice rule in assumption 7 | Dropping `lending_products` since nothing maps to it — tidier, and it deletes the most interesting gap in the analysis |
| 2026-08-09 | Demo message 4 is "I need to update my address on my account", not PLAN §13's "I want to raise my card limit to 50,000" | The plan's wording does not reach the ACTION lane. Banking77 has no card-limit-increase intent, so it resolves to `top_up_limits`, fails citation validity and lands in HUMAN — tested, not assumed. The replacement proposes `update_contact_details` and additionally shows `requires_human_approval: true` and strong auth, which is what §13 wanted the slide to prove | Keeping the plan's wording and explaining on the day why the lane did not fire; or adding a limit-change intent to the frozen taxonomy, which is a worse reason to touch a hand-reviewed file |
| 2026-08-09 | The demo UI renders domain and intent as markdown, not `st.metric` | `st.metric` truncates long values with an ellipsis: "payments_transfers" renders as "paymen…" and "transfer_timing" as "transfer…". Those are the two labels the demo points at, and they were unreadable on a shared screen. Caught by running the app and looking at it, not by reading the code | Keeping `st.metric` for the nicer typography, or fixing the width with custom CSS — which the timebox ruled out and which would break at a different window size anyway |
| 2026-08-09 | All trace field selection lives in `src/trace.py`, via one typed `record_*` method per stage, rather than a generic `log(**kwargs)` | It makes the PII claim auditable in one place: to verify the system never logs customer text you read a single 176-line module, not every agent. A generic logging call would put that judgement at each call site, where it becomes a review discipline instead of a property | A `log(stage, **fields)` helper — far more flexible, and flexibility is precisely the risk when the thing being prevented is a careless field name |
| 2026-08-09 | `Trace.begin` hashes the raw message and keeps only the digest and character count | The trace still supports the operations that matter — correlating repeat contacts, spotting truncation, measuring length drift — with no path back to the text. `message_chars` gives the shape, SHA-256 gives the identity, and neither gives the content | Storing `text_redacted`, which is tempting because placeholders look safe. It still contains the customer's own words, and CLAUDE.md's rule is raw customer text, not just PII values |
| 2026-08-09 | The resolver's `rationale` is recorded as `rationale_chars`, not as text | It is model-authored prose *about* the customer's message, so it can quote it. A length is enough to detect a degenerate or truncated adjudication without opening that channel | Recording the rationale verbatim — genuinely useful for debugging a misroute, and the one field most likely to echo the message back into the sink |
| 2026-08-09 | Blocked and failed messages emit a trace record like any other | An injection that was refused, or a stage that crashed, is exactly the message an auditor asks about. Early returns that skip the sink would leave the incident with no record. Both `_ingress_escalation` and `_failed_closed` now close their trace | Tracing only the messages that completed the pipeline, which is simpler and silently loses every interesting failure |
| 2026-08-09 | Precision, recall, F1, balanced accuracy and the confusion matrix are implemented by hand in numpy rather than imported from sklearn | The complexity budget requires every line to be explainable under questioning, and "sklearn computed it" is not an explanation of a metric that decides whether a fraud message was handled. Verified against sklearn on five random 200-row datasets, agreeing to 1e-9 on every statistic | Importing `classification_report`; shorter, and it makes the one section of the project that is meant to demonstrate statistical competence the one section that outsources it |
| 2026-08-09 | `fraud_recall` and `auto_reply_precision` report a rule-of-three bound alongside their bootstrap interval when the sample has zero variance | 20/20 fraud messages reached a human, so every bootstrap resample also scores 1.0 and the interval collapses to [1.000, 1.000] — an artefact that reads as certainty. The rule of three gives the honest bound: with 20 clean trials the true failure rate could still be 15% | Quoting [1.000, 1.000] as though it were a measured interval, which is the single most misleading number the harness could produce |
| 2026-08-09 | The retrieval ablation is rate-matched rather than threshold-matched | Cosine, BM25 and RRF are on incompatible scales, so no shared threshold is meaningful. Giving each retriever the same budget — flag exactly as many messages as the production gate does — makes precision and recall directly comparable | Tuning a separate threshold per retriever, which turns a component comparison into a comparison of how well each threshold was tuned |
| 2026-08-09 | The threshold sweep varies only the retrieval gate, holding predicted intent fixed at what the system actually produced | The sweep is for choosing one knob. Re-running intent resolution per threshold would cost 10 LLM passes over the gold set and mix adjudicator variance into a curve that is meant to isolate the gate | Re-routing end to end at every threshold — more faithful, ten times slower, and noisier on the axis being read |
| 2026-08-09 | The gold set was rebuilt at 80 rows stratified by FAQ coverage, after the first 100-row version labelled 91% HUMAN | A 0.91 majority baseline makes the benchmark useless: a router that answers "human" unconditionally scores 91%, and no amount of macro-F1 rescues a set that cannot distinguish it from a good one. The cause was oversampling fraud and uncovered intents on a corpus with only 19/77 coverage — every stratum selected for messages the system must refuse. Making the covered pool the largest stratum moves the predicted baseline to 0.50 | Keeping the 100-row set and reweighting at scoring time — the arithmetic works, but with ~9 auto_reply rows the auto_reply precision estimate has no usable resolution whatever the weights |
| 2026-08-09 | `security_fraud` intents are excluded from the covered, uncovered and near-miss pools rather than deduplicated afterwards | Two fraud intents are FAQ-covered, but a covered fraud intent is not auto_reply-eligible — policy forces it to a human regardless of grounding. Letting it into the "auto_reply-eligible" stratum would misrepresent what that stratum measures | Priority-order deduplication as in the first version, which keeps the pools natural but silently mixes forced-HUMAN rows into the pool meant to measure auto-answering |
| 2026-08-09 | Only 1 of 23 existing hand labels was carried into the resample, and no attempt was made to preserve more | Labels could have been preserved by biasing the sampler toward already-labelled messages. Those 23 were the first rows of a file sorted by stratum and domain, so preferring them would skew the new sample toward `account_servicing` and `cards_issuing`. A clean redraw is worth more than 22 saved labels | Seeding each stratum with previously-labelled messages first — saves an hour of work and quietly biases the benchmark toward two domains |
| 2026-08-09 | Accuracy is never emitted without the majority-class baseline beside it, in code rather than by convention | The 91% failure above is precisely what a bare accuracy number hides, and it would have survived into the presentation. `headline_metrics` always returns both, and `print_report` prints the margin over baseline on the line below | Reporting accuracy and leaving the baseline as something to remember to mention |
| 2026-08-09 | "Ambiguous" is defined as a small kNN top-1 to top-2 similarity margin, not by hand-picking confusable intent names | Used in the first gold set to find messages where Stage A cannot decide and the adjudicator determines the outcome. Dropped in the 80-row rebuild, where coverage-based strata matter more, but the margin computation is worth keeping in mind for the ablation on two-stage resolution | Listing intents that look confusable, which measures my intuition about the taxonomy rather than the model's actual uncertainty |
| 2026-08-09 | The gold set is split into two files: `goldset.csv` for labelling and `goldset_strata.csv` held back | The labelling file deliberately omits `faq_covered`, `knn_margin` and `stratum`. A labeller who can see that an intent has no FAQ grounding will label it HUMAN, and the evaluation then measures agreement with the system's own belief instead of correctness. The strata file still lets `run_eval.py` reweight or report per stratum | One file with every column — simpler to handle, and it quietly turns a correctness benchmark into a consistency check |
| 2026-08-09 | Strata are drawn in priority order and partition the sample, rather than overlapping | A fraud message that is also ambiguous belongs to one stratum, so per-stratum counts sum to 100 and can be reweighted without double-counting. Fraud is drawn first because it is the most expensive category to under-sample | Independent overlapping strata, which is closer to how the categories actually relate but makes reweighting ambiguous |
| 2026-08-09 | The retrieval gate thresholds the top-1 **dense cosine**, not the fused RRF score the brief specified | RRF is computed from ranks, so it measures how much the two retrievers agreed, not how relevant the winner is. Measured: a perfect match scores 0.032787 and `exchange_rate` — known-ungrounded, cosine 0.677 — scores 0.032522, which is 99.2% of it. No RRF threshold separates them. Fused rank still decides the *ordering*; cosine decides whether to answer at all | Thresholding RRF as written, which produces a gate that cannot distinguish a good answer from the least-bad of thirty |
| 2026-08-09 | Retrieval threshold is 0.72, chosen on 24 real test messages across 12 intents of known FAQ coverage | Uncovered intents topped out at 0.7163 and covered ones resumed at 0.7687, so 0.72 sits in the gap: 100% precision at 42% recall on that sample. Assumption 8 asks for exactly that trade — rather escalate 40% of answerable messages than send one wrong answer | A lower threshold in PLAN §7's suggested 0.55–0.65 band, which on this data admits `visa_or_mastercard` and `card_arrival`, both genuinely ungrounded. Provisional either way: n=24 and the distributions overlap below the band |
| 2026-08-09 | The RAG prompt carries two worked examples — one refusing, one answering — not just the refusal the brief asked for | With only the refusal shown, the model copied its empty `cited_doc_ids` into every answer, so every grounded reply then failed citation validity and escalated. Observed on `transfer_timing` and `change_pin`, both of which had correct answers and no citations. The refusal example still does its job; it just cannot be the only one | Keeping the single refusal example and relaxing the citation check instead — that would trade a prompt fix for a permanently weaker guardrail |
| 2026-08-09 | The invented-specifics check normalises separators before comparing | `+45 70 20 70 20` and `+4570207020` are the same number. Comparing raw strings would escalate every time the model reformatted a value it had copied correctly, which trains everyone to ignore the alarm | Exact string matching — stricter, and it makes the guard fire mostly on false positives |
| 2026-08-09 | Percentages and durations are deliberately outside the invented-specifics check | The check demands a verbatim match, and "1–2 business days" is routinely reworded without becoming false. Only claims a customer could act on and be harmed by — phone, IBAN, URL, DKK amount — need to survive verbatim | Checking every number, which would escalate almost every grounded reply and make the guard useless |
| 2026-08-09 | `build_escalation` moved from `orchestrator.py` to `agents/handoff_agent.py` | Assembling the handoff is stage 4c's job, not the policy matrix's. Keeping it in the orchestrator was blurring a boundary the whole safety argument rests on — that `decide_disposition` is a pure function with no side responsibilities | Leaving it where Session 3 put it; it worked, but the orchestrator is the one file that should do exactly one thing |
| 2026-08-09 | A 13–19 digit number is redacted as a PAN only if it passes Luhn; a failing number is left in the text | Luhn is what separates a card number from an order reference or a long account ID. Redacting everything digit-shaped destroys the signal the router needs, and the placeholder is meant to preserve the message's shape, not erase it | Redacting every long digit run regardless — safer on paper, but it would blank out reference numbers customers are legitimately asking about, and it makes the guard impossible to reason about |
| 2026-08-09 | CPR is validated on date plausibility (day 1–31, month 1–12) only, not the modulus-11 control digit | CPR numbers issued since 2007 are not guaranteed to satisfy modulus-11. Enforcing it would leave genuine CPR numbers unredacted, which is the worse of the two errors by a wide margin | Full modulus-11 validation, which is the textbook check and would reject real numbers; or shape-only matching, which fires on any hyphenated 6-then-4 digit reference |
| 2026-08-09 | Distress detection short-circuits in `pipeline.py` before intent resolution, rather than becoming a rule in the orchestrator | "Bypasses everything else" is literally control flow, and the orchestrator's contract is a pure function of an `IntentResult` that this path never produces. Routing is correct regardless of topic, so spending an LLM call to discover the topic would only add latency to an urgent handoff. Measured: 220 ms and zero tokens, against 8.5 s on the normal path | Resolving intent first and letting the policy matrix handle the flag — uniform, but it makes a person in crisis wait on a model call whose answer cannot change the outcome |
| 2026-08-09 | The `can't afford` distress pattern is kept despite a measured false-positive rate of 3 in 10,003 Banking77 messages | Measured, not assumed. Two of the three describe genuine financial pressure ("living paycheck to paycheck"), so only one is a true miss. The asymmetry decides it: a false positive costs one unnecessary handoff, a false negative auto-replies to someone in crisis | Tightening the pattern with a negative lookahead for "afford to wait" — it removes the one true false positive by overfitting to a single observed example, which will not generalise |
| 2026-08-09 | `SanitisedMessage` gains `vulnerability_flags: list[str]`, rather than reusing `blocked` | `blocked` means ingress refused the message and nothing downstream runs. Distress is the opposite: the message must be handled, urgently, by a person. Collapsing the two would either drop distress messages or stop blocking injections | Encoding distress as a `block_reason` string; rejected because the two states need opposite downstream behaviour |
| 2026-08-09 | Ingress lives in `src/ingress.py`, not the `src/guardrails/ingress.py` the brief asked for | CLAUDE.md's layout rule is explicit: a directory exists only where there is more than one file and a real reason to group them. `guardrails/` would hold exactly one module. The rule was applied rather than the brief's wording, and flagged for reversal | Creating the package as written — matches PLAN §4, contradicts the convention the repo has followed since the Session 4 flattening |
| 2026-08-09 | The local model is `qwen2.5:3b-instruct`, not PLAN §3's `qwen2.5:7b-instruct` | Hardware, not preference: an 8 GB M1 swaps once a 7B model, the embedding model and Streamlit are all resident. Measured 20/20 first-attempt valid structured output on the adjudicator, so the smaller model is not costing reliability where it matters | The 7B model as planned; rejected on memory. That the swap is one line in `settings.yaml` is exactly the portability argument `LLMClient` exists to make |
| 2026-08-09 | The adjudicator returns `AdjudicatorVerdict` (`chosen_intent`, `reasoning`), not an `IntentResult` | The model is given the smallest possible surface: pick one of five names or null. Code builds the `IntentResult` around that answer, so domain, confidence and candidates are all derived rather than model-authored | Having the LLM emit `IntentResult` directly — fewer moving parts, but it would let a model populate `domain`, which policy reads |
| 2026-08-09 | A `chosen_intent` outside the five candidates is coerced to `None` rather than trusted | Constrained decoding still permits a plausible-looking invented label. Coercion means the shortlist is the entire decision space, enforced after the fact rather than only requested in the prompt | Accepting any valid Banking77 name; rejected because the confidence score is only meaningful for a candidate that Stage A actually surfaced |
| 2026-08-09 | Confidence is the candidate's kNN similarity, discounted by `agreement_penalty` when the adjudicator overrides Stage A's top-1 | Agreement between an embedding neighbourhood and an LLM is the strong signal; disagreement is weaker evidence and should threshold lower. One multiplication, explainable in a sentence | A learned or calibrated combination — better, and unjustifiable without the labelled disposition set that does not exist until Day 5 |
| 2026-08-09 | `decide_disposition` reads only `intent` and `confidence` off the `IntentResult` | The safety property is structural rather than defensive: a fabricated `disposition` field is not blocked, it is never read. The test asserts both that Pydantic drops the key and that the outcome is byte-identical with and without it | Validating or stripping model-authored fields defensively; rejected because a narrow read is a stronger and simpler argument than a filter that must itself be correct |
| 2026-08-09 | `fraud_override` is kept although the taxonomy invariants make it unreachable, and is tested by forging a weakened taxonomy | An unreachable backstop is worthless the day someone relaxes the invariant it duplicates, and untested code is not a backstop. `monkeypatch` builds exactly that future and asserts the override still holds | Deleting it as dead code — defensible today, and it removes the only line standing between a fraud message and an automated reply if `check_safety_invariants` is ever loosened |
| 2026-08-09 | `config/taxonomy.yaml` is frozen after hand-review; no session edits it without asking first | The routing table is now a reviewed artefact, not a draft. An unannounced edit would invalidate the review it passed, and the whole safety argument rests on a human having read every row | Leaving it open to incidental edits as the code around it grows |
| 2026-08-09 | BM25 contributes only the articles it actually matched; zero-scoring articles are dropped before fusion, not ranked | A BM25 score of 0.0 means no shared term, so ranking those articles hands RRF a long arbitrary tail it cannot distinguish from evidence. Measured: on "two-factor authentication" 28 of 30 articles score 0, and the shipped-then-fixed version put doc_001 (blocking a lost card) at fused rank 2 purely on tie order | Ranking all 30 in both lists, which is symmetrical and simpler to explain, but demonstrably wrong on exactly the short rare-token queries BM25 was added to serve |
| 2026-08-09 | Retrieval ranks whole articles and returns them; it never scores its own confidence or abstains | Keeps the abstention gate in one place in Session 4 instead of splitting it between a retriever that half-decides and a policy layer that re-decides. `search()` has no threshold in it at all | Returning `None` or an empty list below a similarity floor — convenient, but it buries a policy decision inside a component that should only rank |
| 2026-08-09 | The Chroma collection stamps its embedding model and query prefix in metadata, and rebuilds itself when either changes | Querying an index built by a different model produces slightly worse answers and no error at all. This is the config-coupling failure found in the Session 2 coverage audit, closed for retrieval | Trusting that whoever edits `settings.yaml` remembers to delete `chroma_db/` |
| 2026-08-09 | `RetrievedArticle` lives in `hybrid.py`, not `schemas.py` | `schemas.py` is the contract between *agents*; retrieval is a component the RAG agent calls, and its diagnostic fields (both retrievers' ranks) exist for inspection, not for the agent boundary. The agent will convert to the existing `Citation` | Putting it in `schemas.py` for uniformity, which would export three ranking fields that no agent should ever branch on |
| 2026-08-08 | `notebooks/` and `slides/` are not tracked | Neither is code, and both would be committed as large binary or output-laden files that no reviewer reads from the repo | Tracking them as §4 specifies; rejected because the exploration notebook's only durable output is the coverage chart, which belongs in `eval/results/` |

## Divergence from PLAN.md

`PLAN.md` is the design document written before any code existed. Where the
as-built repo now differs, the repo is correct and this table is the record:

- **§3, orchestration.** The plan names LangGraph. The pipeline is plain Python
  function calls, per the complexity budget in `CLAUDE.md`. §3's stack table is
  left unedited as the original reasoning; §4's tree has been updated.
- **§4, repository structure.** Flattened as above. §4 has been updated to match
  the as-built layout; `notebooks/` and `slides/` are removed from it, and
  `pyproject.toml`, `DECISIONS.md` and `tests/` are added.
